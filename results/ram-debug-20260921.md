# Debug RAM telemetry

Added RAM fields to the debug `SCREEN` response and a separate label in the GTK
viewer: total RAM, fixed allocation including stack reservations, current heap
reservation, peak reservation since boot, and uncommitted RAM. Old firmware
remains supported; unavailable telemetry is explicit. Disconnection clears the
displayed readings.

The debug-screen build wraps newlib `_sbrk` and observes the actual resulting
break, including optimistic partial growth. Two lock-free counters add 8 bytes
of persistent RAM. It does not inspect allocator lists across cores or expose
memory contents. Heap reservation includes reusable freed blocks, so this does
not measure live allocations or stack high-water usage. The viewer tooltip and
device UI documentation explain those distinctions.

Validation:

- FIDO/debug-screen firmware and no-debug-screen USB-storage firmware built.
- Linked `_sbrk_r` calls `__wrap__sbrk` in the FIDO ELF; the no-debug build has no
  RAM instrumentation symbols.
- `ram_debug` and `device_ui_and_capacity` CTests passed. The RAM test covers
  growth, a peak between samples, shrink, failure, and optimistic allocation.
- Viewer text formatting checked with synthetic values and absent telemetry.
- GTK visual check could not initialize the display in this environment; the
  actual viewer layout and board readings remain to be checked by the user.
- Regenerated `build-pico-fido/fuse_vault_security.uf2` from the rebuilt ELF.
  No flashing, device access or credential changes performed.

The 160×80, 1-bit framebuffer already exists (1,600 bytes). The V2 TFT still
needs initialization and transfer/pixel-conversion code; a line buffer is enough
to avoid a full colour framebuffer.
